# datRail 0.2 capabilities: how each one is demonstrated

| # | ASP Capability | Short description / reference | Sample agent to simulate drift | Demo script (reference) |
| --- | --- | --- | --- | --- |
| 1 | Observed ASP, built every 60 s | RailMon scans the agent's container on an interval and posts an evidence bundle; RailDash shows it as an ASP. No CLI, no restart. (DR-83, DR-158) | The stack's demo agent, as shipped: `docker compose up -d`. Nothing to simulate; the first ASP arrives within a minute, a second with file access a minute later. | A0, A1; CI steps 1 to 2 |
| 2 | Baseline lock, Aligned / Drift detected, accept, switch | Lock an ASP as v1.0; later ASPs compare against it. (DR-120, DR-160) | Click Lock on the newest ASP; status reads ALIGNED. | A2; CI step 3 |
| 3 | Open ingress service port is drift | A listener the baseline did not have. (DR-124, DR-143, DR-182) | `docker exec -d datrail-demo-agent python3 -m http.server 9000 --bind 127.0.0.1`; DRIFT DETECTED at the next scan (15 s in CI at `SCAN_INTERVAL=10`, up to a minute at the default 60), `observed_listeners` shows 9000. | A3; CI step 4 |
| 4 | Kernel-observed file access | filesnoop records each file the agent opens: read, write, exec. (DR-152, DR-185, DR-201) | Same port step shows the files http.server read; the saved-file step below shows a write. | A3, A5; CI steps 4 and 6a |
| 5 | Data Guardrail: no service ports | Adopt the proposal built from the baseline; a port is a violation until allowed. (DR-184) | Adopt after step 3: g1 VIOLATED with 9000 and 8443; Allow all → HELD. | A4; CI step 5 |
| 6 | Data Guardrail: saved-file kinds | A written file outside the allowed kinds. (DR-184, DR-201) | `docker exec datrail-demo-agent sh -c 'mkdir -p /data && echo report > /data/report.zip'`; Saved files VIOLATED at the next scan. | A5; CI step 6a |
| 7 | Data Guardrail: allowed uploads | A file uploaded to a host not in the allowed list; sent to the agent's own server so nothing leaves the machine. (DR-184) | The `exfil.example` POST in the runbook; Uploads VIOLATED, then Acknowledge / Allow this. | A5; CI steps 6b to 6c |
| 8 | Data Guardrail: out-of-spec API/MCP calls | A call to a host or MCP server the agent never declared. (DR-184) | Same POST also lands in Out-of-spec calls; a GET to a second unlisted host is out-of-spec but not an upload. | A5; CI steps 6b, 6d |
| 9 | Data actions from MCP tool schemas (the KubeCon step) | Each tool call classified read / upload / update / delete / execute from the schema the agent was given; unknown tools flagged. (DR-205) | `demo_mcp_call.py upload_file` → `upload · image`; `export_all` → unclassified, then not offered; `--garbage` → unreadable call. | A6; CI steps 6e to 6g |
| 10 | Egress containment | Contained / Open read from Docker; Require containment as a rule. (DR-207) | Demo agent reads Open; Require containment → VIOLATED. The OpenShell sandbox reads Contained (it should not reach outside hosts itself; OpenShell enforces an allow-list) and the rule is held. | A7 and C6; CI step 9 |
| 11 | Agents in an NVIDIA OpenShell sandbox | The agent runs in an OpenShell sandbox; datRail watches it from outside. (DR-206) | `openshell sandbox create` with the demo image and policy; stack pointed at the sandbox container; a GET to api.github.com through OpenShell's supervisor appears. | C1 to C8; CI `openshell` mode |
| 12 | Watching your own agent (Node bundled TLS, gzip streams) | `AGENT_CONTAINER=<yours> docker compose up -d --scale demo-agent=0`; the collector finds the TLS itself. (DR-183, DR-192, DR-213) | A real OpenClaw agent (Node 22) calling Gemini; four model calls captured and paired on a Mac. Candidate for the live demo if we want a real LLM on stage. | B2; INSTALL "Watch your own agent" |
| 13 | Observed traffic | Hosts, calls, bytes per host, tool calls, models. (DR-91 to 93, DR-148) | Any of the above; the Observed security profile panel. | A1, B2 |
| 14 | Declared config and identity | MCP servers, credential names, image digest; per-run values never count as drift. (DR-115, DR-123, DR-193) | Inspect evidence on any ASP; restart the agent and show that `agent_instance` changes without drift. | A1 |
| 15 | Runs on x86_64 / arm64 Linux, WSL2, Mac via Docker Desktop | Verified on Apple Silicon on 10/15, 10/20 and 10/23 (image-only install); `make test` runs on a Mac since DR-254. (DR-208, DR-212, DR-254) | Not a drift item; a slide. | INSTALL.md, Platform support |
| 16 | Optional: bundles also sent to Rail Center | `RAIL_CENTER_URL` set; same bundle to `/v1/agents/register`. (DR-188) | Not in the OSS demo unless a Rail Center is up. | INSTALL "Sending bundles to Rail Center" |
| 17 | Blocked by OpenShell | What OpenShell's supervisor refused the sandboxed agent, read by the opt-in `openshell-collector`; neither the denial nor the request it refused is a violation, since nothing left the sandbox. (DR-249, DR-250, DR-261) | `docker exec $A touch /sandbox/post`: a POST to api.github.com that the read-only rule refuses; it shows under Blocked by OpenShell and counts against no guardrail rule (DR-261). | C9; CI `openshell` mode |
| 18 | Enforce the guardrail with OpenShell | **Download as OpenShell policy**: the guardrail in force as an OpenShell policy file (every endpoint audit, gaps in its header), applied and rolled back by the user. (DR-258, DR-259) | Download, `openshell policy set my-agent --policy <file> --wait`, then roll back through `policy get --rev N --base --output json`. | C10; CI `openshell` mode |
